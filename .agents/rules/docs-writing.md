# 文件撰寫規範 (Documentation Writing Rules)

本規範適用於專案中所有文件撰寫、維護與說明內容的產出（包含 `README.md`、架構說明、API 文件、操作手冊及程式碼註解）。

---

## 1. 核心原則 (Core Principles)

* **清晰精煉 (Clarity & Conciseness)**：避免冗贅與模糊敘述，優先使用直接、結構化、條列式的說明。
* **以使用者/讀者為核心 (Audience-Centric)**：區分目標讀者（一般使用者、初學者、開發維護者），提供對應深度的說明與範例。
* **及時更新 (Living Documentation)**：程式碼結構、依賴項目或部署流程變更時，必須同步更新相關文件，避免資訊落差。
* **解釋「為什麼」而非僅「做了什麼」 (Explain the "Why")**：說明設計決策、架構選型與潛在限制，而不僅重複描述程式碼字面動作。

---

## 2. 語言與語調 (Language & Tone)

* **主要語言**：以繁體中文 (Traditional Chinese) 為主，專業技術術語、變數名稱、指令可保留英文。
* **語調**：保持客觀、專業、友善且具引導性。
* **標點與排版規範**：
  * 中英文之間保留一個半形空格（例如：「使用 Git 進行版本控制」）。
  * 專有名詞、指令、路徑、檔案名稱一律使用行內代碼（`code span`）標示，例如 `index.html`、`git push`。

---

## 3. Markdown 排版標準 (Markdown Standards)

* **標題層級**：
  * 每個文件僅有一個一級標題（`# Document Title`）。
  * 標題嚴格依階層遞增（`##` -> `###` -> `####`），不可跳級。
* **程式碼區塊**：
  * 所有代碼塊必須標註語法高亮語言標籤（如 `html`、`css`、`javascript`、`bash`、`json`、`markdown`）。
  * 指令範例應標明工作目錄或前後關聯。
* **GitHub 風格提示框 (Alerts)**：
  * 善用區塊引言標註重要提示，避免文字混雜：
    * `> [!NOTE]`：補充背景或說明。
    * `> [!TIP]`：最佳實踐或操作小技巧。
    * `> [!IMPORTANT]`：關鍵步驟或必須注意之先決條件。
    * `> [!WARNING]`：可能造成錯誤或中斷的注意事項。

---

## 4. 標準專案 README.md 結構範本

專案的 `README.md` 應包含以下標準章節：

1. **專案名稱與簡介**：一兩句話說明專案的核心目的與價值，可附上在線 Demo 連結（如 GitHub Pages）。
2. **核心特色 (Features)**：條列式列出 3~5 項核心功能亮點。
3. **技術堆疊 (Tech Stack)**：列出所使用的語言、框架、工具與第三方庫。
4. **專案目錄結構 (Project Structure)**：使用 ASCII 樹狀圖簡要說明主要檔案結構與用途。
5. **快速開始 / 本地執行 (Getting Started)**：
   * 環境先決條件 (Prerequisites)。
   * 安裝與啟動步驟（包含確切命令列指令）。
6. **部署與線上版本 (Deployment)**：說明如何構建或部署至 GitHub Pages 等平台。
7. **貢獻指南與授權 (License & Contributing)**：註明開源授權（如 MIT）及協作原則。

---

## 5. 程式碼註解規範 (Code Commenting)

* **模組/檔案開頭**：重要模組頂部應提供簡短概述（說明檔案職責）。
* **重要函式**：對複雜函式提供參數說明、回傳值型別與副作用描述。
* **業務邏輯與 Edge Cases**：針對複雜演算法、特殊防錯邏輯、瀏覽器相容性調整提供背景說明。
* **避免無意義註解**：避免撰寫顯而易見的註解（例如 `i++ // i 加 1`）。
